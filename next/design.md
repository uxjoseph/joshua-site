# JOSHUA 디자인 시스템

조슈아앤컴퍼니 웹사이트의 디자인 언어를 정의합니다.
구현체는 `app/globals.css` 한 파일이며, 이 문서의 토큰과 1:1로 대응합니다.

---

## 1. 원칙

우리는 엔터프라이즈 AX를 다룹니다. 화면이 스스로를 설명하려 들면 다루는 내용이 가벼워
보입니다. 그래서 이 시스템은 **덜어내는 방향**으로 설계했습니다.

| # | 원칙 | 구체적으로 |
|---|---|---|
| 1 | **순백 캔버스** | 기본 배경은 `#fff`. 섹션마다 배경색을 바꿔가며 구분하지 않는다 |
| 2 | **헤어라인은 구분자에만** | 섹션·행·리스트 경계는 1px `#e1e1e1` 선 하나로. 요소를 두르는 데는 쓰지 않는다 |
| 3 | **윤곽선 대신 면** | 버튼·카드는 테두리가 아니라 면(`--glass`·`--canvas-soft`)으로 선다 |
| 4 | **거의 직각** | 라운드는 4~16px. 면적이 커져도 자라지 않는다 |
| 5 | **그림자 없음** | elevation 개념을 쓰지 않는다. 깊이는 여백으로만 만든다 |
| 6 | **좌측 정렬 + 비대칭 2단** | 제목은 최좌측, 본문은 오른쪽 칼럼으로 |
| 7 | **강조색은 점으로만** | 파랑은 화살표·링크·포커스에만. 면으로 칠하지 않는다 |

원칙 4·5는 함께 지켜야 의미가 있습니다. 둥근 모서리와 그림자는 대개 세트로 쓰이고,
둘 중 하나만 빼면 어중간해집니다.

원칙 2·3도 한 쌍입니다. 선은 **무언가를 나누는** 일만 하고, 요소의 존재는 면이
알립니다. 한 요소에 테두리와 면을 동시에 주면 둘 다 약해집니다.

> 히어로는 **가운데 정렬**입니다(원칙 6의 유일한 예외). 첫 화면은 레이아웃이 아니라
> 한 문장이 앵커이고, 그 문장은 화면 가운데에 있어야 합니다.

원칙 1의 예외는 **밴드**뿐입니다(7장). 배경색은 구분이 아니라 리듬을 만드는 장치이고,
그래서 한 페이지에 두세 개로 제한합니다. 나머지 섹션 경계는 전부 헤어라인이 담당합니다.

## 2. 색상

### 중립 — Light

| 변수 | 값 | 용도 |
|---|---|---|
| `--canvas` | `#ffffff` | 페이지 배경 |
| `--card` | `#ffffff` | 면 배경 |
| `--canvas-soft` | `#f8f8f8` | 행 hover |
| `--strong` | `#f9fafb` | 이미지 로딩 플레이스홀더 |
| `--hairline` | `#e1e1e1` | **모든 구분선** |
| `--hairline-strong` | `#c8cacd` | 인풋 테두리 |

### 글래스 면

테두리 없이 **면만으로 서는** 요소들이 공유하는 틴트입니다. 불투명 회색이 아니라
잉크를 얹어 뒤를 한 톤 누르는 방식이라, 흰 배경 위에서는 연회색으로 읽히면서도
뒤에 있는 것(히어로 파티클, 다크 밴드)이 비쳐 층위가 살아 있습니다.

| 변수 | 값 | 용도 |
|---|---|---|
| `--glass` | `rgba(0,0,0,.06)` | 네비 캡슐, 고스트 버튼, 카드 CTA |
| `--glass-dark` | `rgba(255,255,255,.1)` | 다크 밴드 위에서의 같은 요소 |
| `--nav-surface` / `--nav-surface-dark` | `var(--glass)` / `var(--glass-dark)` | 네비 전용 별칭 |

항상 `backdrop-filter: blur(…) saturate(160%)`와 함께 씁니다. blur 없이 틴트만 주면
그냥 반투명 회색 박스이고, 유리로 읽히지 않습니다. 네비는 `blur(42px)`, 나머지는 `blur(20px)`.

**한 톤으로 묶는 것이 규칙입니다.** 면만으로 서는 요소가 서로 다른 농도를 쓰면
같은 층위로 읽히지 않습니다.

### 텍스트 · 잉크

| 변수 | 값 | 용도 |
|---|---|---|
| `--ink` | `#000202` | 제목, 본문 강조 |
| `--body` | `#414143` | 본문 |
| `--muted` | `#727272` | 보조 텍스트 |
| `--muted-soft` | `#919191` | 캡션 |
| `--dark` | `#0b0b0b` | Primary 버튼 배경 |

> 사이트는 **전면 라이트**입니다. 다크 섹션이 없으므로 `--band` `--dark-elev` `--on-dark`
> `--on-dark-soft` 토큰은 제거했습니다. 다크 면을 다시 도입하려면 토큰부터 정의하고
> 아래 밴드 절에 추가하세요.

### 강조

| 변수 | 값 | 용도 |
|---|---|---|
| `--accent` | `#0621c4` | 화살표, 링크, 포커스 링 |
| `--accent-soft` | `#0621c433` | 포커스 배경 |
| `--accent-wash` | `#0621c40d` | 아주 옅은 강조 배경 |
| `--accent-on-dark` | `#8fa2ff` | 다크 밴드 위의 강조색 |

`--accent`는 **흰 배경 기준**으로 고른 진한 청색입니다. 다크 밴드(`#0e0f12`) 위에서는
대비가 1.3:1 로 사실상 보이지 않으므로, 어두운 면에서는 반드시 `--accent-on-dark`(8:1)를
씁니다. 밝은 면과 어두운 면에 같은 강조색을 쓸 수 없다는 뜻입니다.

> **금지**: 파스텔 그라데이션, `filter: blur()` 로 만든 색 블롭, 다색 그라데이션.
> 색은 정보 위계를 나타낼 때만 쓰고 장식으로 쓰지 않습니다.

## 3. 타이포그래피

**Pretendard**. 한글·영문·숫자가 한 패밀리 안에서 균일하게 붙는 것이 이 사이트의 전제입니다.

```css
--font: "Pretendard Variable", Pretendard, -apple-system, "Apple SD Gothic Neo", sans-serif;
```

### 웨이트

`400` 본문 · `500` 라벨·버튼·링크 · `600` 제목

제목은 **600 단일 웨이트**입니다. 한 제목 안에서 얇은 획과 굵은 획을 섞지 않습니다.

### 제목의 강조는 색으로

굵기 대신 **색**으로 강조합니다. `<strong>`이 잉크(`--ink`)를 가져가고 나머지는
회색(`--muted`)으로 물러납니다.

```
AX는 일회성 프로젝트가 아니라   ← --muted #727272
여정입니다                    ← --ink   #000202  (<strong>)
```

```css
h1:has(strong), h2:has(strong), h3:has(strong) { color: var(--muted); }
h1 strong, h2 strong, h3 strong { color: var(--ink); }
```

`:has()`를 쓰는 이유는 **강조가 없는 제목을 보호**하기 위해서입니다. `/privacy`의
`개인정보처리방침`이나 상세 페이지의 동적 제목처럼 `<strong>`이 없는 제목은 잉크 그대로
남아야 합니다. `:has()` 미지원 브라우저에서는 전부 잉크로 렌더되므로 안전하게 퇴화합니다.


### 스케일

| 역할 | 크기 | 웨이트 | 행간 | 자간 |
|---|---|---|---|---|
| 히어로 `h1` | `clamp(2.5rem, 6vw, 5.5rem)` | **700** | 1 | `-.045em` |
| 섹션 `h2` | `clamp(1.875rem, 3.2vw, 2.25rem)` | 600 | 1.1 | `-.03em` |
| `h3` | `clamp(1.0625rem, 1.4vw, 1.25rem)` | 600 | 1.3 | `-.02em` |
| `.lead` | `clamp(1rem, 1.4vw, 1.125rem)` | 400 | 1.5 | 0 |
| 본문 | `1rem` / `.9375rem` | 400 | 1.5 | 0 |
| 캡션·메타 | `.8125rem` | 400 | 1.5 | 0 |

### 자간 규칙

- 제목은 **음수 자간**(`-.03em`). 큰 글자는 자간이 벌어져 보이므로 조여줍니다.
  히어로 `h1`은 88px까지 커지므로 한 단계 더(`-.045em`, 행간 `1`) 조입니다.
  같은 값이어도 글자가 커질수록 헐거워 보이기 때문입니다.
- 히어로 `h1`의 `<strong>`은 **웨이트를 함께 올려야** 합니다. 전역에서 `strong`이 600으로
  고정돼 있어 부모만 700으로 올리면 강조 부분이 오히려 얇아집니다.
- 본문은 **`0`**. 한글에 양수 자간을 주면 단어 덩어리가 풀어집니다.
- **대문자 변환(`text-transform: uppercase`)과 넓은 자간(`letter-spacing: .1em`) 라벨을
  쓰지 않습니다.** 오버라인·카테고리도 그냥 작은 회색 텍스트로 둡니다.
- 모든 한글 텍스트에 `word-break: keep-all`.

## 5. 형태

| 항목 | 값 | 쓰는 곳 |
|---|---|---|
| `--pill` | `4px` | 버튼, 태그, 네비 캡슐 |
| `--r-md` | `6px` | 인풋, 메뉴 항목, 썸네일 액자 |
| `--r-xl` | `8px` | **카드** |
| `--r-xxl` | `12px` | 큰 면 |
| `--card-r-lg` | `clamp(12px, 1vw, 16px)` | 히어로형 대면적 카드 |
| `--nav-r` | `4px` | 네비 캡슐(= `--pill`) |
| `--badge-r` (배지 전용) | `9999px` | 배지 |
| `--bw` (버튼·인풋 테두리) | `1.5px` | |
| 구분선 | `1px` | |
| `--shadow` | `none` | |

**스케일 기준은 8px입니다.** 카드가 8px이고 나머지를 그 위아래로 촘촘히 붙였습니다.
값의 폭이 좁은 것이 의도입니다 — **면적이 커져도 라운드는 거의 자라지 않아야**
각진 인상이 유지됩니다. 폭 1178px짜리 `.cta-card`도 16px에서 멈춥니다.

라운드는 절대 픽셀이 아니라 **요소 높이 대비 비율**로 판단합니다. 레퍼런스 스크린샷에서
값을 옮길 때 특히 그렇습니다 — 2x 캡처의 8px을 그대로 16px로 옮기면, 우리 요소가
더 낮을 때 훨씬 둥글어집니다.

예외는 `--badge-r` 배지 하나뿐입니다. 예전에 예외였던 네비 캡슐(`--nav-r`)과
대면적 카드(`--card-r-lg`)는 스케일 안으로 들어왔습니다.

### 배지만 알약 — 유일한 예외

각진 언어에서 **배지 하나만** 곡선을 씁니다. 카드 안에서 배지는 색이 들어가는 유일한
자리인데(7장 「카드」), 여기에 모서리까지 얹으면 진입점이 한 번 더 분명해집니다.
면적이 작아 각진 인상을 흩뜨리지 않으면서 시선은 확실히 잡습니다.

`--pill`과 **분리된 토큰**을 쓰는 이유는 버튼 때문입니다. `.btn`도 `--pill`을 참조하고
있어서 `--pill`을 `9999px`로 바꾸면 버튼까지 알약이 됩니다. 배지만 둥글게 하려면
토큰이 따로 있어야 합니다.

| 요소 | 토큰 | 모서리 |
|---|---|---|
| `.step-en` `.tech-card .no` `.pf-card .cat` `.edu-card .client` `.ins .cat` | `--badge-r` | 알약 |
| `.btn` `.tag` `.sol-talos .chips span` | `--pill` | 4px |

`.tag`(준비 중 · 카테고리)는 **직각으로 남깁니다.** 채운 면이 아니라 테두리만 있는
무채색 칩이라 배지와 다른 계열이고, 제목 옆에 인라인으로 붙는 자리라 알약이 되면
글줄 안에서 튑니다.

알약은 가로 여백이 좁으면 양끝이 눌려 보입니다. 직각일 때보다 **가로 패딩을 넉넉히**
잡습니다 — `.85rem` → `1.05rem`.

## 6. 레이아웃

| 항목 | 값 |
|---|---|
| `--max-w` | `1440px` |
| `--gutter` | `clamp(1.25rem, 4vw, 5rem)` |
| 네비 높이 | `64px` |

### 비대칭 2단 — 이 레이아웃의 핵심

모든 섹션이 따르는 구조입니다.

```
┌─────────────────────────────────────────────────┐
│ AX는 일회성 프로젝트가 아니라 여정입니다          │  ← h2, 최좌측, 풀폭
│                                                 │
│              ┌──────────────────────────────┐   │
│              │ 본문 / 이미지 / 리스트        │   │  ← 38% 들여쓰기
│              │                              │   │
│              └──────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

제목이 왼쪽 끝을 잡아주고 본문이 오른쪽으로 물러나면, 스크롤할 때 제목만 세로로 이어지는
축이 생깁니다. 1000px 이상에서만 적용하고 그 아래는 단일 칼럼으로 떨어집니다.

```css
@media (min-width: 1000px) {
  .section .inner > .lead { margin-left: 38%; }
}
```

자식 선택자로 구현했으므로 **페이지 마크업을 바꾸지 않고** 적용됩니다.

## 7. 컴포넌트

### 버튼

hover에서 전경/배경을 **반전**시킵니다. 밝기만 조금 바꾸는 방식은 쓰지 않습니다.

| | 기본 | hover |
|---|---|---|
| Primary | 배경 `--dark` · 글자 `--strong` | 배경 `--glass` · 글자 `--ink` |
| 고스트 | 배경 `--glass` · 글자 `--ink` | 배경 `--ink` · 글자 `#fff` |

**버튼에 윤곽선을 쓰지 않습니다.** 기본에도, hover에도. 고스트 버튼은 테두리가 아니라
글래스 면(`--glass` + `blur(20px) saturate(160%)`)으로 섭니다.

선을 쓰지 않는 이유는 짝 때문입니다. 옆에 놓이는 Primary가 면(잉크)인데 한쪽만
윤곽선을 두르면 두 버튼이 **다른 종류의 요소로** 읽힙니다. 둘 다 면이면 "잉크 면 ↔
글래스 면"의 대비가 되어 같은 계열의 두 단계로 읽힙니다.

hover도 마찬가지입니다. 평소엔 선이 없다가 hover에만 윤곽선이 생기면, 상태가 아니라
버튼 종류가 바뀐 것처럼 보입니다.

> **`border`는 지우지 말고 `transparent`로 둡니다.**
> `border: none`으로 없애면 `--bw`(1.5px)만큼 높이가 줄어 옆의 Primary와 3px 어긋납니다.

적용 대상: `.btn-outline` · `.card .more` · `.storyx-cta` · `.pf-nav button`.
다크 면 위(`.cta-card`, 다크 밴드의 `.storyx-cta`, 다크 밴드의 네비 CTA)에서는
`--glass-dark`로 틴트의 **부호만 뒤집습니다.** 밝은 구간에선 면, 어두운 구간에선
윤곽선이 되면 같은 버튼이 두 종류로 보입니다.

### 링크 화살표

```css
.sec-link::after { content: " →"; color: var(--accent); }
.sec-link:hover::after { transform: translateX(4px); }
```

파랑이 등장하는 거의 유일한 자리입니다. 화살표 하나에만 색을 주고 텍스트는 잉크로 둡니다.

### 네비 캡슐

화면 폭을 가로지르는 띠가 아니라 위에서 떨어져 떠 있는 **콘텐츠 폭 캡슐**입니다.
`.nav`은 가운데로 몰아주는 투명 껍데기(`pointer-events:none`)이고, 면은 `.nav-inner`가
갖습니다 — 캡슐 좌우의 빈 공간이 아래 콘텐츠 클릭을 막지 않게 하려는 것입니다.

| 항목 | 값 |
|---|---|
| 모서리 | `--nav-r` `4px` |
| 면 | `--glass` + `backdrop-filter: blur(42px)` |
| 테두리 · 그림자 | **없음** |
| 다크 밴드 위 | `--glass-dark` (틴트의 부호만 반전) |

유리를 세 겹(그라디언트 + inset 하이라이트 + 드롭섀도)으로 쌓던 방식은 걷어냈습니다.
**틴트 한 겹과 blur만** 남깁니다. 얹혀 있는 조각이 아니라 뒤 배경을 눌러 만든 면으로
읽혀야 합니다.

다크 밴드 대응은 `TechScroller`가 `<html>`에 붙이는 `data-story-dark`로 합니다.
네비는 `position: fixed`라 섹션 셀렉터로 닿지 않으므로 루트 신호가 필요합니다.

### 포트폴리오 레일 — 프레임이 이미지 비율을 따른다

`.pfx-item`의 `aspect-ratio`는 고정값이 아니라 **각 이미지의 원본 비율**(`--pfx-ar`)입니다.
이미지 로드 시 JS가 넣습니다.

고정 프레임(예: `16/10`)을 쓰면 비율이 다른 원본마다 남는 쪽에 매트가 깔립니다.
스크린샷 배경도 대부분 흰색이라, 그 매트가 **이미지를 덮은 흰 띠**로 보이고 결국
잘린 것처럼 읽힙니다. 패딩으로 여백을 키우면 띠가 두꺼워질 뿐입니다.
비율을 맞추면 띠가 아예 생기지 않습니다.

> **스테이지 높이(`--pfx-h`)는 가장 세로로 긴 원본에 맞춥니다.**
> 더 낮으면 그보다 높은 카드가 `overflow:hidden`에 잘리고, 더 높으면 빈 띠가 남습니다.
> 스크린샷을 교체해 더 세로로 긴 원본이 들어오면 이 값도 함께 내려야 합니다.

> **비율 주입은 `onLoad`로 하지 않습니다.** 캐시된 이미지는 핸들러가 붙기 전에
> 이벤트가 지나가고, `complete` 플래그도 백그라운드 탭에서는 `false`로 남습니다.
> `naturalWidth`를 기준으로 즉시 한 번 적용하고 `load`·`decode()`로 뒤를 받칩니다.

**스크린샷 에셋은 경계에서 내용이 끊기지 않아야 합니다.** 풀블리드 앱 캡처는 파일
경계에서 UI가 잘려 있기 마련이고, 그건 CSS로 되돌릴 수 없습니다. 잘린 요소가 없는
지점까지 크롭해서 내보냅니다. 원본은 `.asset-backup/`에 둡니다.

### 네비 드롭다운

`.drop-menu`는 트리거 버튼에서 10px 띄워 놓습니다. 그러면 커서가 그 틈을 지나는 순간
`.drop:hover`가 풀려 메뉴가 닫히고 **아래쪽 항목을 클릭할 수 없습니다.**

```css
.drop-menu::before{ content:""; position:absolute; left:0; right:0; top:-12px; height:12px }
```

투명 브리지로 틈을 잇습니다. `.drop-menu`의 자손이므로 닫힌 상태의 `pointer-events:none`을
함께 물려받아, 닫혀 있을 때 실수로 열리는 일은 없습니다.

### 리스트 행

카드로 감싸지 않고 **헤어라인으로만 구분된 행**을 씁니다. 세로 패딩을 넉넉히 주고
hover에 `--canvas-soft`를 아주 옅게 깝니다. `.pf-row` `.edu-row` `.faq`가 이 패턴입니다.

### 카드

**면 카드** (`.card` `.sol-talos` `.sol-next` `.ins` `.pf-card` `.edu-card`) — 테두리 없이
면으로만 구분합니다. 원칙 1의 "순백 캔버스"는 **섹션**에 대한 규칙이고, 카드는 면을
가질 수 있습니다. 다만 테두리와 면을 동시에 쓰지는 않습니다 — 둘 중 하나면 충분합니다.

흰 섹션 위의 연회색 카드는 경계가 약합니다. 그래도 **헤어라인을 덧대지 않습니다** —
그 약한 경계가 오히려 카드를 띄워 놓은 종이처럼 읽히게 합니다.

**글래스 카드** (`.tm` 팀 프로필) — 면 대신 `--glass` 틴트 + `blur(24px)`를 씁니다.
테두리도 그림자도 없습니다. 흰 배경 위에서 선 하나 없이 떠 보여야 하는 자리에 씁니다.
선을 그으면 그 순간 문서처럼 읽힙니다.

> **카드 면은 섹션과 반대입니다.**
>
> | 섹션 배경 | 카드 면 |
> |---|---|
> | 흰 섹션 | `--canvas-soft` `#f8f8f8` |
> | 연회색 밴드 | `--canvas` `#ffffff` (`.tech-card`) |
>
> 같은 색을 쓰면 카드가 사라집니다. 그리고 카드 면은 **불투명**이어야 합니다 — 밴드에
> 깔린 그리드 닷이 본문 뒤로 비치면 가독성이 떨어집니다.

> **안쪽 여백은 상하좌우 균일, 카드마다 같은 값입니다.**
>
> ```css
> padding: var(--card-pad);   /* = --sp-5, 28 → 30px */
> ```
>
> | 카드 | 열 | 폭(1440 기준) | 패딩 |
> |---|---|---|---|
> | `.card` `.ins` | 3열 | 467px | `--card-pad` |
> | `.sol-talos` `.sol-next` | 7fr / 5fr | 817 / 583px | `--card-pad` |
> | `.pf-card .pad` | 3열 | 467px | `--card-pad` |
> | `.tech-card` | 4열 | 345px | `--card-pad` |
> | `.edu-card .pad` | 4열 | 345px | `--card-pad` |
>
> 두 가지를 지킵니다.
>
> **세로와 가로를 다르게 주지 않습니다.** 위아래를 좌우보다 넓게 잡으면 카드가 세로로
> 늘어져 보이고, 3열·4열이 섞인 페이지에서 카드마다 다른 비율이 생깁니다.
>
> **카드 폭에 따라 값을 바꾸지 않습니다.** 넓은 카드에 넓은 패딩을 주는 편이 비율로는
> 맞지만, 그러면 한 화면에 놓인 카드들의 글줄 시작선이 서로 어긋납니다. 카드는 폭이
> 달라도 같은 규격의 상자로 읽혀야 하므로 **절대값을 고정**합니다. 4열 카드(345px)에서는
> 패딩이 폭의 8.7%까지 올라가 다소 넉넉하지만, 정렬의 일관성이 더 중요합니다.
>
> 값을 조정할 때는 `--card-pad` 한 곳만 고칩니다. 개별 카드 규칙에 `--sp-*`를 직접
> 쓰면 이 통일이 깨집니다.

카드 안의 위계는 네 단으로 만듭니다.

```
┌──────────────────────────────────────┐
│  ▪ 01 · Learn — 기업교육              │  ① 배지 — 파랑 on 옅은 파랑. 카드의 유일한 색
│                                      │
│  조직이 AI를 이해하게 만듭니다          │  ② 제목 — 21px / 600 / --ink
│  카카오뱅크·신한은행이 선택한…          │  ③ 본문 — 15px / 400 / --muted
│  ──────────────────────────────      │
│  — 임원 특강 …                        │     리스트 — 헤어라인으로 분리
│                                      │
│  [ 교육 사례 보기 → ]                  │  ④ 액션 — 흰 면 + 테두리 박스
└──────────────────────────────────────┘
```

- **배지**(`.step-en` `.ins .cat`)가 진입점입니다. 카드에서 색이 들어가는 유일한 자리이고,
  나머지는 전부 무채색이라 시선이 여기서 시작합니다.
- **액션**은 `margin-top: auto`로 바닥에 고정합니다. 3열의 본문 길이가 달라도 버튼 줄이
  가로로 맞습니다.
- 배지는 `--badge-r`을 따라 **알약**입니다. 각진 언어에서 유일한 예외이고, 카드 안의
  진입점을 색과 모서리로 이중 표시합니다. 근거는 5장 「배지만 알약」을 보세요.

**이미지 카드** (`.pf-card` `.edu-card`) — 같은 면 카드에 이미지를 얹은 변형입니다.
이미지는 카드 상단에 **풀블리드**(패딩 밖까지)로 놓고 텍스트만 패딩 안으로 들어옵니다.
카테고리(`.cat` `.client`)는 배지로 올려 진입점을 만듭니다.

이미지 자체에는 테두리를 두르지 않습니다(`.sol-shot` 포함). 카드의 면이 이미 경계를
만들고 있어서, 테두리를 더하면 선이 겹쳐 보입니다.

### 밴드 — 섹션 리듬

풀블리드로 면을 깐 섹션입니다. 흰 섹션이 이어지는 사이에 한 번씩 놓아 리듬을 만듭니다.
**강조 수단이 아니므로 한 페이지에 세 개 이상 두지 않습니다.**

밴드는 **연회색 한 종류**뿐입니다 — `--canvas-soft`(`#f8f8f8`). Technology와 하단
Contact 두 곳에 씁니다.

밴드 안에서는 **면을 하나만** 씁니다.

| | 처리 |
|---|---|
| Technology | 카드를 흰 면(`--canvas`)으로 — 카드가 면을 갖는다 |
| Contact | 폼 패널을 두지 않는다(`transparent`) — 인풋만 흰 면을 갖는다 |

Contact 폼에 패널 면을 두지 않는 이유는, 밴드 위에 흰 패널을 얹으면 단단한 블록으로
튀기 때문입니다. 반투명 + `backdrop-filter`로 완화해봐도 어중간하게 남습니다. 폼의 형태는
인풋 테두리가 충분히 만들어 주므로 패널은 여백만 담당하게 두는 편이 깔끔합니다.

#### 그리드 닷 — 정적

Contact 밴드에는 **좌측 하단 빈 공간에만** 아주 옅게(`--accent` `.045`) 깝니다. 좌하단
코너에서 퍼져나가며 사라지는 마스크를 겹쳐, 카피와 폼 영역에는 닿지 않습니다. 여기는
모션 없이 정적입니다 — 파문은 Technology 한 곳으로 충분합니다.

#### 그리드 닷 — 중앙에서 퍼지는 물결

Technology 밴드에만 28px 격자의 점 패턴을 깔고, 중앙에서 링이 퍼져나가며 지나는 자리의
점을 진하게 만듭니다. 점 색은 `--accent`를 아주 낮은 불투명도(`.05`, 링 `.2`)로 씁니다 —
장식이므로 배경에 묻히는 선을 넘지 않습니다.

> **점 격자는 `background`가 아니라 `mask`로 씁니다.** 그리고 그 레이어는 절대
> `transform`하지 않습니다.
>
> 반복 패턴을 `scale`하면 **점 간격까지 같이 늘어납니다.** 두 겹을 서로 다른 배율로
> 애니메이션하면 간격이 다른 격자가 겹쳐 보여 "중복된 점 그리드"처럼 읽힙니다.
> 격자를 마스크로 고정해두고 그 **뒤에서 링만** 움직여야 격자가 하나로 유지됩니다.

```
.tech-dots            점 격자 마스크 + 바닥 색   ← 고정, transform 없음
  ├ ::before          파문 링 (scale 애니메이션)
  └ ::after           파문 링 (-4s 지연)
```

마스크는 자손까지 함께 자르므로, 두 링 모두 같은 격자를 통과합니다. 링은 가운데가 빈
`radial-gradient` 고리이고 `scale(.04) → scale(1)`로 커지며 사라집니다. 두 개를 반주기
어긋나게 두어 파문이 끊기지 않습니다.

**`transform`과 `opacity`만 애니메이션합니다** — GPU 합성이라 리페인트가 없습니다.
`mask-size`나 `background-position`으로 파문을 만들면 매 프레임 전체 리페인트가 일어나므로
쓰지 않습니다.

바닥 점은 중앙이 진하고 가장자리로 갈수록 사라지는 radial 그라디언트라, 밴드 경계에서
점이 잘리지 않습니다. `prefers-reduced-motion`에서는 링을 숨기고 바닥 격자만 남깁니다.

이 장식만 마크업에 전용 엘리먼트(`<div class="tech-dots">`)가 필요합니다. 마스크를 건
부모와 움직이는 자식이 분리돼야 하는데 `::before`/`::after`는 서로 형제라 부모-자식이
될 수 없기 때문입니다.

## 8. 히어로 모션

`public/particle-funnel.js` — Canvas 2D로 그리는 수렴 레인 + 시그널 트레일.
히어로 배경 레이어(`z-index: 0`)에 깔리고 본문은 그 위(`z-index: 1`)에 옵니다.

```
lineColor       #0621c4   --accent
lineOpacity     0.18      반투명 — 배경 틴트가 그대로 비쳐 이질감이 없다
signalColor     #0621c4   --accent (레인과 같은 색을 불투명하게)
bgColor         null      투명
convergeSpread  0.07      한 줄로 합치지 않고 좁은 띠로 모은다
convergePointX  62        화면상 수렴점은 38% 위치 (아래 반전 주의사항 참고)
```

레인과 시그널이 **같은 색상값**을 공유합니다. 레인은 18% 불투명도의 옅은 자국, 시그널은
같은 파랑을 불투명하게 — 하나의 색으로 두 개의 레이어를 만듭니다. 중립 회색을 쓰면
푸른 배경 위에서 색이 겉돌기 때문에, 배경이 무엇이든 어울리는 반투명 강조색을 씁니다.

### 부채꼴은 오른쪽, 띠는 왼쪽

퍼널의 레인은 **한쪽 끝에서 최대로 벌어져 수렴점에서 모입니다.** 즉 부채꼴은 구조적으로
한쪽에만 생기고, 카피와 같은 쪽에 두면 반드시 겹칩니다. 좌측 정렬 레이아웃이므로
캔버스를 좌우 반전해 부채꼴을 오른쪽으로 보냅니다.

```css
.hero-funnel canvas { transform: scaleX(-1); }
```

반전의 부수 효과로 시그널이 오른쪽에서 왼쪽으로 흐르며 CTA 버튼 쪽으로 수렴합니다.

> **반전은 반드시 `canvas`에 겁니다.** 래퍼(`.hero-funnel`)에 걸면 transform이 마스크까지
> 함께 뒤집어 `to right` 그라디언트가 화면상 왼쪽으로 적용됩니다.
>
> **`convergePointX`의 방향도 뒤집힙니다.** 화면상 수렴점은 `100 - convergePointX` % 위치에
> 옵니다. **값을 올리면 수렴점이 왼쪽으로** 갑니다. 직관과 반대이므로 조정 전에 확인하세요.
>
> | `convergePointX` | 화면상 수렴점 | 부채꼴이 차지하는 폭 |
> |---|---|---|
> | 45 | 55% | 오른쪽 45% |
> | 62 | 38% | 오른쪽 62% ← 현재 |
> | 75 | 25% | 오른쪽 75% |

### 수직 위치 — 카피와 CTA 사이

퍼널은 **캔버스의 세로 중심**에 그려집니다(`cy = h / 2`). 라이브러리에 오프셋 옵션이 없으므로
CSS로 캔버스 자체를 올립니다.

```css
.hero-funnel { top: -6%; bottom: 6%; }   /* 높이는 유지한 채 위로만 이동 */
```

`top`과 `bottom`에 같은 값을 반대 부호로 주면 `height = 컨테이너 - top - bottom`이 그대로
유지되면서 요소만 올라갑니다. 이렇게 띠를 lead 문단과 CTA 버튼 **사이 공백**에 앉힙니다.

> **세로 마스크도 함께 움직입니다.** 마스크는 요소 높이 기준이므로 오프셋을 바꾸면
> 마스크 위치도 같이 이동해 띠 아래쪽을 잘라먹습니다. 오프셋을 조정할 때는 마스크
> 구간도 같이 봐야 합니다.

### 마스크

세로 한 겹만 씁니다.

```css
mask-image: linear-gradient(to bottom, #000 0, #000 50%, transparent 76%);
```

로고 마퀴로 넘어갈 때만 사라지고, **좌우로는 끊기지 않고 화면 끝까지 관통**합니다.
가로 마스크가 필요 없는 이유는 레인이 18% 불투명도라 카피 근처를 지나도 읽기를 방해하지
않기 때문입니다.

> 히어로에는 **불투명 흰색 요소를 두지 않습니다.** 흰색으로 덮어 가리는 방식은 배경이
> 순백일 때만 성립하고, 배경 이미지가 깔리면 흰 패치로 드러납니다. `.btn-outline`의
> 배경을 `transparent`로 두는 이유가 이것입니다.

### 등장 — 마지막에 디졸브

파티클은 카피가 다 올라온 뒤 **마지막에** 서서히 배어 나옵니다.

```css
.hero-funnel { animation: funnel-in 2.4s ease-out 1.1s both }
@keyframes funnel-in { from { opacity:0 } to { opacity:1 } }
```

히어로의 마지막 `.reveal`이 450ms 지연 + 0.7s로 약 1.15s에 끝나므로, 1.1s에 시작해
2.4s에 걸쳐 들어옵니다. `both` fill-mode가 지연 구간 동안 `opacity:0`을 유지합니다.

### 배경 이미지

`public/bg.png`를 `.hero::before`에 `opacity: .4`로 깔고 아래쪽은 페이드로 다음 섹션에
넘깁니다. 파티클 레인과 카피를 눌러 죽이지 않을 만큼만 옅게 씁니다.

26s 주기로 아주 느리게 확대·이동합니다(`scale(1.06)` → `scale(1.12) translate(-2%,-1.5%)`).
`alternate`로 왕복하므로 루프가 이어지는 지점에 점프가 없습니다. CSS 그라디언트가 아니라
래스터 이미지이므로 **`transform`이 유일한 저비용 수단**입니다 — GPU 합성이라 리페인트가
없습니다.

> `transform`은 이 요소의 `mask`까지 함께 움직입니다. 스케일 폭이 6%뿐이라 하단 페이드
> 경계가 밀리는 양은 눈에 잡히지 않지만, 폭을 크게 키우면 페이드 위치가 눈에 띄게
> 흔들립니다.

`prefers-reduced-motion`에서는 파티클은 정지 프레임 한 장, 배경은 정지 상태로 둡니다.

## 9. 스크롤 등장

`.reveal`이 붙은 요소는 화면에 들어올 때 아래에서 떠오릅니다(`translateY(24px)` → `0`,
0.7s). 관찰은 `components/Effects.tsx`의 IntersectionObserver가 맡습니다.

### 한 덩어리씩 — 스태거

한 섹션이 통째로 나타나면 덩어리가 커서 둔합니다. **같은 섹션 안에서는 DOM 순서대로
90ms씩 지연**을 줘 순차적으로 등장시킵니다. 섹션이 바뀌면 0부터 다시 시작합니다.

```
히어로:  h1(0) → 문제줄(90) → lead(180) → CTA(270) → 지표(360) → 로고(450)
```

지연은 인라인 `transition-delay`가 아니라 **커스텀 프로퍼티**로 넣습니다.

```css
.reveal { transition: opacity .7s var(--ease) var(--reveal-delay, 0ms),
                      transform .7s var(--ease) var(--reveal-delay, 0ms); }
```

`transition-delay`를 직접 주면 등장이 끝난 뒤의 hover 전환까지 늦어집니다. 커스텀
프로퍼티는 `.reveal` 트랜지션에만 참조되므로 그런 부작용이 없습니다.

6단계에서 상한을 둬(`Math.min(i, 6)`) 항목이 많은 섹션에서 마지막 요소가 지나치게 늦게
나타나지 않게 합니다. 마크업에는 `.reveal` 하나만 붙이면 되고 순서 지정은 필요 없습니다.

### 스태거 엔진 — 자식도 하나씩

`.reveal`은 **컨테이너**에 붙어 있어서, 그대로 두면 카드 4장이나 리스트 7행이 한 덩어리로
뜹니다. 컨테이너 자신의 페이드는 끄고 자식이 순번(`--i`)에 따라 순차 등장합니다.

```css
:where(모든 컨테이너).reveal   { opacity:1; transform:none; transition:none }
:where(모든 컨테이너).reveal>* {
  opacity:0; transform:translateY(var(--rise,20px)) scale(var(--shrink,1));
  transition:opacity var(--dur,.7s) cubic-bezier(.16,.84,.44,1)
             calc(var(--reveal-delay,0ms) + var(--i,0)*var(--step,90ms)), transform … }
:where(…).reveal.in>*          { opacity:1; transform:none }
:where(…).reveal>*:nth-child(2){ --i:1 }   /* …8번째부터 --i:8 로 상한 */
```

순번 규칙은 **한 번만** 정의하고 계열별로 파라미터만 바꿉니다.

| 계열 | 컨테이너 | `--step` | `--dur` | `--rise` | `--shrink` |
|---|---|---|---|---|---|
| 카드 | `.grid3` `.sol-grid` `.tech-grid` `.pf-feature` `.edu-feature` `.ins` `.team` `.timeline` | 130ms | .8s | 30px | .97 |
| 리스트 행 | `.pf-list` `.edu-tbl` `.faq` `.proof-band` `.tech-proof` | 65ms | .6s | 14px | 1 |

카드는 크고 느리게, 행은 작고 촘촘하게 — 요소 크기에 맞춰 리듬을 다르게 줍니다.

> **지연은 두 값을 더합니다** — `--reveal-delay`(섹션 안 컨테이너 순번) + `--i × --step`
> (컨테이너 안 자식 순번). `--i`만 쓰면 자식이 제목·리드와 **동시에** 시작해서 섹션
> 전체가 한꺼번에 튀어나오는 것처럼 보입니다. 두 값을 더해야 오버라인 → 제목 → 리드 →
> 자식1 → 자식2 … 로 이어지는 하나의 흐름이 됩니다.

> **컨테이너를 추가할 때는 마크업에 `.reveal`이 있는지 먼저 확인하세요.** 셀렉터에
> `.reveal`을 필수로 넣었지만, 반대로 `.reveal`이 없는 컨테이너를 목록에 넣으면 `.in`이
> 붙지 않아 자식이 영구히 `opacity:0`으로 남습니다. `.team`은 이 때문에 마크업에
> `.reveal`을 추가했습니다.

> **셀렉터에 `.reveal`을 반드시 넣습니다.** 그리드 클래스만으로 잡으면 `.team`처럼
> `.reveal`이 없는 컨테이너까지 걸립니다. 그러면 `.in`이 절대 붙지 않아 **카드가 영구히
> `opacity:0`으로 남습니다.** 그리드 클래스를 추가할 때는 해당 마크업에 `.reveal`이
> 있는지 먼저 확인하세요.

`:where()`로 묶어 특이도를 0으로 유지하므로 각 카드의 자체 스타일과 충돌하지 않습니다.
지연은 여기서도 `transition-delay` 직접 지정이 아니라 `--card-delay` 커스텀 프로퍼티입니다.

### 히어로 h1 — 마스크 슬라이드업 (`.reveal`의 예외)

히어로 `h1`만 공용 `.reveal`을 끄고(`opacity:1; transition:none`) 별도 모션을 씁니다.
88px짜리 헤드라인이 24px 슬라이드업으로 통째로 뜨면 **크기에 비해 이동량이 작아 보여**
움직임이 빈약합니다.

```html
<h1 class="reveal">
  <span class="line">          <!-- overflow:hidden 마스크 -->
    <span class="w">당신의</span> <span class="w">첫</span>
    <strong class="w">AX 파트너</strong>
  </span>
</h1>
```

단어(`.w`)가 `translateY(110%)`로 줄 아래에 숨어 있다가 제자리로 올라옵니다.
`.in`이 붙으면 70ms 간격으로 차례로 밀려 나옵니다.

**투명도를 건드리지 않는 것이 핵심입니다.** 페이드를 섞으면 글자가 "켜지는" 느낌이지만,
가려진 곳에서 올라오면 "밀고 나오는" 느낌이 됩니다. 큰 헤드라인에서 이 차이가 큽니다.

> **마스크에는 상하 여유가 필요합니다.**
> `line-height: 1`을 그대로 자르면 한글 위아래가 깎입니다. `padding-block: .09em`으로
> 열어 두고 같은 값의 음수 마진으로 레이아웃 높이를 되돌립니다.
>
> 이때 **`h1`에 `display: flow-root`가 필요합니다.** 없으면 음수 마진이 부모를 통과해
> (마진 병합) 상쇄되지 않고, 마스크 패딩만큼 `h1`이 통째로 높아집니다(77 → 91px).

> **`prefers-reduced-motion`에 반드시 넣습니다.** 여기서는 위치로 숨기기 때문에,
> 규칙이 빠지면 단어가 마스크 뒤에 숨은 채로 **영영 보이지 않습니다.**

## 10. 접근성

- 본문 `--body` `#414143` on `#fff` → 대비 **10.6:1**
- 보조 `--muted` `#727272` on `#fff` → 대비 **5.2:1** (본문 크기 이상에서만 사용)
- 포커스 링은 `--accent` 2px, `outline-offset: 3px`. 어떤 요소에서도 제거하지 않습니다.
- `.reveal` 스크롤 애니메이션(카드 순차 등장 포함), 로고 마퀴, 그리드 닷 파문, 히어로
  파티클은 모두 `prefers-reduced-motion`에서 정지합니다.
- 인풋 `min-height: 44px` — 터치 타깃 최소 크기.

## 11. 적용 범위

토큰과 컴포넌트 레이어가 `app/globals.css` 한 곳에 있으므로,
클래스명을 공유하는 **11개 라우트 전체에 자동 반영**됩니다.

```
/  /work  /work/[slug]  /solutions  /solutions/micky  /solutions/talos
/education  /insights  /insights/[slug]  /contact  /privacy
```

새 페이지를 만들 때는 기존 클래스(`.section` `.inner` `.lead` `.card` `.pf-row` …)를
재사용합니다. 새 클래스가 필요하면 먼저 이 문서에 패턴을 추가하고 구현합니다.

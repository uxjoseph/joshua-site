## 0. 한 줄 요약

교육·TALOS·구축 3개 사업을 "AX 여정"이라는 단일 서사로 묶은 리드젠 허브로 joshua.site를 재구축한다.
뉴스레터를 본 도메인에 통합해 SEO·GEO(생성엔진 최적화) 자산을 joshua.site 한 곳에 쌓는 것이 이번 개편의 전략적 핵심이다.

## 1. 배경

### 1.1 사업 구조 (확정)
| 축 | 사업 | 성격 | 웹사이트에서의 역할 |
|---|---|---|---|
| ① | **B2B 교육** (기업강의) | 기존 주력, 레퍼런스 보유 | 신뢰 구축 + 콜드 리드 유입 관문 |
| ② | **B2B AX OS** (TALOS) | 온톨로지 설치·솔루션 납품 (제조업 중심) | 제품 브랜드. **SEO·GEO 최우선 타깃** |
| ③ | **B2B AX 구축** (에이전시) | 컨설팅 + 구현 | 고단가 핵심 전환 |

- TALOS는 별도 랜딩(talos 서브도메인, 광고 유입용) 운영 중 — 본체 개편 시 본 도메인 내 소개 페이지와 역할 분담 필요.
- 조쉬 뉴스레터를 joshua.site로 통합 예정 (현재 /newsletter 라우트는 차단 상태).

### 1.2 현 사이트 문제
- 원페이지 구조(히어로→선언→기능→프로세스→포트폴리오→FAQ→문의)라 3개 사업이 구분·설명되지 않음.
- Vite CSR SPA — 본문이 JS 렌더링이라 검색엔진·AI 크롤러가 콘텐츠를 읽기 어려움. SEO/GEO 요구와 정면 충돌.
- 콘텐츠 발행 채널이 없음(뉴스레터는 외부, 블로그 부재) → 검색 유입 자산 0.

## 2. 벤치마크 핵심 발견 (3사 비교)

| 항목 | Enhans | Dalpha | Letsur |
|---|---|---|---|
| 포지셔닝 | "Enterprise AI for Real Work" — 실행 서사 | "World Model" 단일 기술 내러티브 | "비즈니스 AI 전환 파트너" — 여정 서사 |

| IA | 메가메뉴 (일부 404, 과복잡) | 3메뉴 극단 미니멀 | 허브형이나 도메인 파편화 (외부 도메인 다수) |
| 콘텐츠/SEO | 뉴스룸 주 1~2회, 타깃 키워드 저격 | 정의형 콘텐츠 + JSON-LD 조직 스키마 (최상급) | 블로그 외부 호스팅(inblog) — SEO 유출 |
| 리드젠 | 다단계 폼 + 웨비나 CTA | 3필드 초저마찰 폼 | 단일 CTA 수렴 + 문의 유형 드롭다운 + 24h SLA |
| 신뢰 | 벤치마크 순위·수상·집단 크레덴셜 | 투자·팀 서사·개인 인용문 | 수치 사례(40일→10분)·실명 후기·연혁 |

**종합 시사점 (조슈아 적용 원칙)**
1. **여정 프레임**(Letsur) + **실행 한 문장 포지셔닝**(Enhans)으로 3개 사업을 묶는다. 나열 금지.
2. **모든 콘텐츠·SEO 자산은 joshua.site 단일 도메인에 귀속**(Letsur 반면교사). 뉴스레터·블로그·사례 전부.
3. **정의형 콘텐츠 + 구조화 데이터**(Dalpha)로 검색·AI 인용을 선점한다. GEO의 실체는 "AI가 인용하기 좋은, 출처가 명확한 정의·수치·FAQ"다.
4. IA는 작게, 전 페이지 살아있게(Enhans 반면교사). 리브랜딩/라우트 변경 시 리다이렉트 필수(기존 SPA Fallback Rule).
5. 수치 박힌 사례·약속("6주 파일럿", "24시간 내 답변")이 소규모 회사의 체급을 올린다. 단, Education Data Rule — 실제 자료 기반만.

네비게이션 6개 이하 유지 (Enhans 반면교사, Dalpha 미니멀리즘 참고):

```
joshua.site
├── /                    홈 — 여정 서사 + 3사업 관문 + 사례 + 인사이트 + 단일 CTA
├── /education           B2B 교육 (기존 페이지 개편 승계)
├── /solutions           ★ 솔루션 허브 — TALOS를 포함한 솔루션 포트폴리오의 상위 메뉴
│    └── /solutions/talos   TALOS 소개 — 온톨로지/제조 AX 설명 중심 (SEO 페이지)
│                            └ 전환 CTA는 talos 서브도메인 랜딩 또는 공용 문의 폼으로
│                            (후속 솔루션은 /solutions/<name>으로 확장)
├── /work                사례 모음 — 문제→해결→수치 카드 (교육/구축/솔루션 필터)
├── /insights            ★ 뉴스레터 + 블로그 통합 허브 (SEO·GEO 엔진)
│    └── /insights/:slug    개별 글 (정적 생성 필수)
├── /about               회사·조쉬 소개 — 개인 서사·연혁·미디어 (Dalpha 팀 페이지 참고)
```

- 네비: 교육 · **솔루션(드롭다운: TALOS, 이후 확장)** · 사례 · 인사이트 · 회사소개 + CTA "문의하기"

- 기존 라우트 리다이렉트: `/newsletter/*` → `/insights/*` (301). `/education` 유지.
- 푸터: 3사업 사이트맵 + 뉴스레터 구독 폼 + 사업자 정보(스키마와 일치).

## 6. SEO / GEO 전략 (사업축 ② 핵심 요구)

### 6.1 기술 기반 — 렌더링 전환 (필수 선결)
현 Vite CSR로는 SEO/GEO 달성 불가. 옵션:

| 옵션 | 내용 | 판단 |
|---|---|---|
| A. Vite + prerender | vite-ssg/prerender 플러그인으로 정적 HTML 생성 | 마이그레이션 최소, /insights 동적 글 관리가 취약 |
| **B. Next.js (App Router) 전환** | Vercel 네이티브, SSG+ISR, 메타·sitemap·OG 자동화 | **권장.** 콘텐츠 허브 운영에 최적, 기존 React 컴포넌트 재사용 가능 |

- 권장: **B**. 기존 섹션 컴포넌트(Framer Motion 포함)를 이식하고, /insights는 MDX 또는 CMS(TBD) 기반 SSG.

### 6.2 온페이지/구조화 데이터
- JSON-LD: Organization(회사·대표·주소·sameAs), Service×3(교육/구축/TALOS), Article(인사이트), FAQPage(각 사업 페이지)
- sitemap.xml + robots.txt + **llms.txt** (GEO: AI 크롤러용 사이트 요약)
- 페이지별 고유 title/description, OG 이미지 자동 생성
- 기존 하네스 규칙 준수: 새 라우트마다 `curl -sI` 200 확인, rewrite 규칙 유지

### 6.3 GEO 운영 원칙
- AI가 인용하기 좋은 형태로 쓴다: 명확한 정의 문단(2~3문장), 수치+출처, Q&A 블록, 일관된 회사 표기("조슈아앤컴퍼니 Joshua & Company")
- 유입 경로 폼 항목에 "AI 검색(ChatGPT·Perplexity 등)" 포함해 GEO 성과 실측 (Enhans 참고)
